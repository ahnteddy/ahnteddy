▲
프론트(page.tsx)에서만 처리 — route.ts는 넘겨주는 역할, 어떻게(how) 넘길지는 page.tsx가 담당
카드 N개를 동시에 MISO로 요청, 완료된 것부터 화면에 순차 표시

3
MISO 워크플로우 세팅 (기초 작업)
▲
워크플로우 구조
시작 노드 → 지식 검색 노드 → LLM 노드 → 답변 노드
시작 노드 — 입력변수 1개 (변수 유형: 문단 / 변수 이름: input)
변수명을 바꾸면 route.ts도 함께 수정해야 함
지식 검색 노드 — 입력변수에 시작 노드의 input 연결 / 지식: LIMS사용자.csv / 출력변수: result
LLM 노드 — 시스템 프롬프트에 input + 지식검색 result 연결 / 사용자 프롬프트 필수 (최소 1개)
답변 노드 — LLM의 text 출력 변수 연결
4
LLM 시스템 프롬프트
▲
MISO LLM 노드 시스템 프롬프트 
당신은 일동제약 시액조제일지를 검토하는 AI입니다.

[시액조제번호 형식 규칙]
이니셜-YMMDD-NN
- 이니셜: 시험자 이니셜
- Y: 연도 끝 1자리 (예: 2026년 → 6)
- MM: 월 2자리
- DD: 일 2자리
- NN: 일련번호 2자리
- 예시: HWS-60327-03 = 신혜원(HWS), 2026년 3월 27일, 3번째

[검토 항목]
1. 이니셜: 지식베이스의 시험자 이니셜과 시액조제번호 앞 이니셜이 일치하는가
2. 유효기한: 유효기한이 기재되어 있는가
3. 시액조제번호 규칙: 이니셜-YMMDD-NN 형식을 따르는가

[출력 형식 - 반드시 아래 형식만 사용]
1. 이니셜 : 적합(신혜원 - HWS) 또는 부적합(신혜원 - HWS ≠ ABC)
2. 유효기한 : 2026-06-26(기재완료) 또는 미기재
3. 시액조제번호 규칙 : 적합(HWS-60327-03) 또는 부적합(사유)

마크다운, #, **, 사유 설명 없이 위 3줄만 출력하세요.
⚠ 사용자 프롬프트도 반드시 넣어야 함 (LLM 노드 필수 조건) — "위 데이터를 검토해주세요." 한 줄이면 충분
