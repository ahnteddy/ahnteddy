태윤 — 오프닝
▲
전체 구조 설계 · 오프닝 발표
1
기획의도 및 취지 소개
일동제약이 앞으로도 지속적으로 성장하는 만큼, 늘어나는 검토 업무를 보다 효율적으로 처리하기 위해 AI를 도입
단순 반복 검토 업무에 AI를 적용하여 시험자와 검토자 모두의 업무 부담을 절감
2
팀원 소개
태윤 — 전체 개발 방향 설정 및 프론트 ↔ AI 연결 총괄
혜원 — 프론트엔드. UI 설계 및 사용자 경험 최적화
하람 — 백엔드. AI(MISO) 워크플로우 및 지식베이스 설계
3
시스템 구조 설명
v0 + Vercel 와 MISO를 이용해서 프론트엔드와 백엔드 구축
그 외 사용자의 편의 와 직관성을 고려한 기능 추가
해커톤을 준비하면서 Vercel과 MISO 뿐만 아닌 다양한 개발언어 및 AI를 학습하였음을 언급
2
혜원 — 프론트엔드 & 디테일
▲
프론트엔드 개발 · UI 디테일 · 발표
1
v0로 UI 초안 생성 + GitHub 연동
AI 기반 UI 생성 도구(v0)로 초안을 빠르게 제작
웹하드 역할을 하며 수정 및 배포가 용이한 GitHub에 연동하여 효율성 극대화
v0 수정 시 평균 00분 소요 → GitHub 직접 수정 시 00분으로 단축
간단한 수정은 코드를 직접 보고 수정하는 것이 디버깅에 더 빠르다고 판단
⚠ 실제 시간 수치 측정 후 입력 필요
2
UI 디테일 소개
도메인 — 누구나 접근하기 쉽도록 직관적인 도메인 설정
예: 시액조제일지.com (연 9천원 수준, 타 팀 대비 차별화 포인트)
반응형 UI — 시험자(태블릿)와 검토자(PC) 각각의 디바이스에 최적화된 레이아웃 설계
아이콘 — 좌측 상단 아이콘 배치로 완성도 높은 프로그램 이미지 구현
차별화 포인트: 도메인 구입은 타 팀이 생각하지 못할 디테일
3
하람 — 백엔드 & 시연 & 클로징
▲
백엔드 · MISO 연동 · 시연 · 클로징 발표
1
프론트엔드 시연
화면을 직접 보여주며 사용자 입력 → AI 응답까지의 흐름 설명
입력값을 바로 AI에 넘기면 할루시네이션(착란)이 발생할 수 있어, 파싱을 먼저 수행함을 기술적으로 언급
기술 포인트: "파싱 로직 구현을 위해 Python을 별도로 학습했습니다"
2
지식베이스 데이터 구성
AI가 검토에 활용하는 DB 구조 설명
일반 사용자는 접근 불가 — 관리자 계정만 추가/수정/삭제 가능한 보안 구조 설명
관리자 기능도 프론트 화면에서 직접 조작 가능하도록 구현
차별화 포인트: 단순 챗봇이 아닌, 실무에 바로 쓸 수 있는 완성형 관리 시스템
3
기대효과 및 마무리
업무 시간 단축 — 반복 검토 업무의 자동화로 시험자/검토자 업무 효율 향상
오류 감소 — AI 기반 1차 검토로 휴먼에러 사전 방지
확장 가능성 — 시액조제일지 외 다양한 문서 검토에 동일 구조 적용 가능
